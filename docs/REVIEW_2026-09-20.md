## What is built

Next.js dashboard plus FastAPI backend; image upload, domain selection, streaming stage progress, entity overlays, reasoning text, critic report, final verdict, metrics, input validation, stage caching, and optional Ollama/vLLM adapters. Four stages separate mapping, deliberation, critique, and synthesis. The interface clearly labels synthetic mode.

## Must address before a convincing AI demonstration

1. **Run genuine inference and evaluate it.** `backend/pipeline/demo_engine.py` creates seeded random entities and boxes, template reasoning, and a simple image-statistics anomaly score. These are useful interface fixtures, not detection accuracy. The included crop-stress illustration returned NOMINAL / no action required despite its deliberately drawn stress patch. This is evidence about the fallback only, not the untested model.
2. **Remove misleading demo throughput.** The browser displayed 1,420 tokens/sec and the API returned 710 generated tokens despite no model inference. The demo engine records fixed token counts and derives speed from them. Its synthetic flag/banner is good, but the metric should read simulated or unavailable rather than look like a model benchmark.
3. **Make critic handling match the promise.** `backend/pipeline/orchestrator.py` stops on stage errors but does not gate final output on `verified: false`. Critique is passed into synthesis as context; it is not an enforced veto. Schema validation is not verification of factual correctness. Either enforce a needs-review policy for failed critique or describe this accurately.
4. **Replace unsupported claims with evidence.** `docs/benchmarks.md` explicitly contains representative figures and a real-inference template. Measure latency and resource use on the actual model and hardware. No confidence-calibration evaluation was found. Claims about calibrated confidence, sub-pixel detection, complete coverage, and approximately 4 GB VRAM need evidence or narrower wording. Distinguish AWQ from GGUF Q4_K_M and stage-result caching from cross-stage model KV reuse.
5. **Choose one environmental user and workflow.** Agriculture inspection or post-flood assessment is a clearer story than seven diagnostic domains. Use appropriately sourced images with expected outcomes, include a normal and abnormal example, and show how uncertainty affects the recommended next action. Treat visual findings as inspection support.

## Secondary cleanup

- Landing/dashboard footers still say SPEED Virgo Challenge although current submission documentation targets NextStep Hacks.
- README backend quickstart changes into `backend` and then imports `backend.main`; running from the repository root avoids that import-path problem.
- Frontend default proxy targets port 8000. This review used the supported `NEXT_PUBLIC_API_BASE` override to avoid the running CrisisWatch backend.
- Model discovery can fall back to a non-vision model when no vision model is found; service availability alone should not imply a usable model.
- The orchestrator shares a mutable metrics tracker across requests; concurrent-request metrics deserve isolation. This is a source-review concern, not a reproduced concurrency failure.
- npm audit reports one high and one moderate dependency finding involving PostCSS/Next. Review and update before public deployment; advisories alone do not establish that this app is exploitable. No exploit reproduction was performed.
- Python dependencies are broadly unpinned; installing pydantic-ai pulls many provider integrations. Tighten dependency scope and lock versions for reproducibility.
